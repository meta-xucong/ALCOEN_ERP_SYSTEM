# 正式合同生成器开发方案

## 1. 方案定位

本功能不再作为“交易合同”页面中的打印按钮，而是独立建设一个正式合同业务板块：

```text
AI CATS / ERP
└── 正式合同生成器
    ├── 正式合同列表
    ├── 新建正式合同
    ├── 正式合同详情
    ├── 模板管理
    └── 已同步交易合同
```

正式合同生成器负责：

- 维护正式合同需要的甲方档案和合同信息。
- 根据正式合同模板生成 DOCX 文件。
- 沿用当前发货单、对账单的浏览器打印流程完成打印。
- 将正式合同内容一键同步为 ERP 的“交易合同”。

交易合同模块仍然负责原有的订单、发货、回款、开票和对账业务。

当前模板文件：

5. 合同条款：

   - 结算方式及期限

6. 甲乙方资料表：

1. 受控占位符模板：使用 `{{ contract.contract_no }}` 等字段，由 `docxtpl` 渲染。
2. 当前提供的固定版式模板：识别合同编号表、产品明细表和甲乙方资料表，在不要求用户改写原始 DOCX 的情况下按固定位置填充。

原始模板文件不直接修改，系统保存一份模板版本副本；每次生成的 DOCX 另存为独立文件。

## 3. 总体业务流程

### 3.1 新建正式合同

1. 用户进入“正式合同生成器”。
2. 点击“新建正式合同”。
3. 在甲方名称下拉框中选择已有公司，或直接输入新公司名称。
4. 系统根据甲方名称查找正式合同甲方档案。
5. 如果存在历史记录，自动加载最近一次生成的甲方资料和默认合同字段。
6. 用户在此基础上修改。
7. 选择或输入产品明细。
8. 填写合同编号、签订地点、签订时间和合同条款。
9. 点击“保存并生成合同”。
10. 系统保存正式合同记录和数据快照，生成 DOCX 文件。
11. 页面提供：
    - 预览
    - 打印
    - 下载 DOCX
    - 一键同步到交易合同

### 3.2 选择已有公司

甲方下拉框支持：

- 公司名称模糊搜索。
- 选择已有公司。
- 输入新公司名称。

选择已有公司后，加载顺序为：

1. 该公司正式合同生成器最近一次使用的甲方资料。
2. 如果正式合同档案没有资料，则读取 ERP 公司资料。
3. 仍然为空的字段保持空白，由用户补充。

用户修改后的内容默认只作用于当前正式合同，不直接覆盖 ERP 公司资料。这样可以避免正式合同中的临时开票信息误改交易合同模块的基础资料。

可以增加一个管理员专用选项：

```text
同步更新 ERP 公司资料
```

只有明确勾选并通过权限校验后，才更新现有 Company 记录。

### 3.3 新公司处理

如果用户输入的甲方名称在 ERP 公司库和正式合同甲方档案中都不存在：

1. 创建 ERP `Company` 记录。
2. 创建正式合同甲方档案记录。
3. 当前正式合同关联新建的甲方档案。
4. 后续交易合同可以直接选择该公司。

上述操作必须在一个数据库事务中完成，任何一步失败都整体回滚，避免只创建半条公司数据。

操作：

- 合同编号
- 签订地点
- 签订时间

甲方名称为主字段。选择甲方后，其余甲方信息和最近一次合同默认信息自动填入。

#### 卡片二：甲方资料

- 公司名称
- 开票地址
- 公司电话
- 税号
- 开户银行
- 银行账号

#### 卡片三：产品明细

- 序号
- 产品名称
- 产品编码
- 规格型号
- 数量
- 单价
- 金额
- 删除

- 查看数据快照

打印页面沿用当前发货单和对账单机制：

- 支持自动打印和手动打印。
- 通过 `afterprint` 关闭窗口或回收 iframe。

## 5. 数据模型设计

新增模型，不复用交易合同记录承载正式合同草稿。

### 5.1 FormalContractParty

正式合同甲方档案，以甲方名称作为主要识别字段。

建议字段：

| 字段 | 说明 |
|---|---|
| id | 主键 |
| party_a_name | 甲方名称，规范化后唯一 |
| company_id | 可空，关联 ERP 公司表 |
| billing_address | 开票地址 |
| phone | 公司电话 |
| tax_no | 税号 |
| bank_name | 开户银行 |

| source | erp_company/manual |
| last_used_at | 最近使用时间 |
| created_at | 创建时间 |
| updated_at | 更新时间 |

`party_a_name` 用于下拉搜索，`company_id` 用于复用 ERP 公司数据。

### 5.3 FormalContractItem

正式合同产品明细。

建议字段：

| 字段 | 说明 |
|---|---|
| id | 主键 |
| formal_contract_id | 正式合同 ID |
| product_id | 可空，关联 ERP 产品 |
| product_code | 快照产品编码 |

| 字段 | 说明 |

## 6. 模板设计和实际模板适配

### 6.1 模板占位符与固定版式

当前 Word 模板需要在开发阶段转换为受控占位符，例如：

```text
{{ contract.contract_no }}
{{ contract.sign_place }}
{{ contract.sign_date }}
{{ party_a.name }}
{{ party_a.billing_address }}
{{ party_b.name }}
{{ party_b.tax_no }}
```

合同编号不由系统自动生成，也不强制检查格式或重复性。选择已有甲方时，系统只自动载入该甲方最近一次正式合同使用的合同编号，用户可以直接修改或清空。

产品表使用可重复行：

```text
{% for item in contract.items %}
{{ item.product_name }}
{{ item.product_model }}
{{ item.quantity }}
{{ item.unit_price }}
{{ item.total_amount }}
{% endfor %}
```

合计区域使用：

```text
{{ contract.total_amount }}
{{ contract.total_amount_upper }}
```

模板引擎只允许白名单字段，不允许执行任意代码。

如果上传的是本次提供的固定版式 DOCX，系统会自动识别其三张核心表格并填充合同基础信息、产品明细、条款和甲乙方资料，无需手工插入占位符。

### 6.2 模板更换规则

管理员更换模板时：

1. 上传新的 DOCX 模板。
2. 系统检查扩展名、文件大小和占位符。
3. 系统报告缺少字段和未知字段。
4. 管理员预览测试数据。
5. 确认后启用新版本。
6. 旧模板改为停用，不删除。

历史正式合同使用生成时的模板版本，不能因为管理员换模板而改变。

### 6.3 模板管理与数据录入解耦

模板只负责版式，数据库负责业务数据。

例如：

- 产品名称来自产品库。
- 甲方基本资料来自正式合同甲方档案和 ERP 公司库。
- 结算条款来自正式合同记录或默认配置。
- 模板不能决定产品数量和合同总价。

这样更换模板不会改变业务数据。

## 7. 一键同步到交易合同

### 7.1 同步原则

同步必须调用现有交易合同创建服务或复用现有合同创建流程，不能在正式合同模块中复制一套合同创建逻辑。

同步结果应与用户手动进入“交易合同”后创建的结果一致。

### 7.2 字段映射

| 正式合同生成器 | 交易合同 |
|---|---|
| party_a_name | company_name/company_id |
| contract_no | contract_no，按用户填写内容同步 |
| product_id | product_id |
| product_name | product_name |
| product_code | product_code |
| product_model | product_model |
| quantity | 计划数量/合同数量 |
| unit_price | 单价 |
| total_amount | 总价 |
| sign_date | 合同日期 |
| 条款和备注 | 合同备注或扩展字段，按现有字段能力映射 |

交易合同无法直接承载的字段，不应丢失。可以在同步关系或正式合同快照中保留，并在交易合同备注中写入摘要。

### 7.3 同步前检查

点击“一键同步到交易合同”前检查：

- 正式合同已生成。
- 甲方已关联 ERP 公司。
- 产品明细不为空。
- 产品明细中的产品已关联产品库，或者已按规则创建产品。
- 数量大于零。
- 单价和总价符合现有合同规则。
- 当前用户拥有交易合同创建权限。

### 7.4 同步事务

同步过程应在一个数据库事务中完成：

1. 校验正式合同。
2. 创建或确认公司。
3. 创建或确认产品。
4. 调用交易合同创建服务。
5. 创建 `FormalContractSync` 关系。
6. 提交事务。

任何一步失败都回滚，不留下半成品交易合同。

### 7.5 防重复同步

同一份正式合同默认只能成功同步一次。

同步成功后：

- 按钮变为“查看交易合同”。
- 显示交易合同编号。
- 再次点击不重复创建。

如确实需要再次生成，应由用户明确执行“复制为新正式合同”，而不是重复同步原记录。

## 8. 权限设计

建议新增权限：

```text
formal_contract_view
formal_contract_create
formal_contract_edit
formal_contract_generate
formal_contract_print
formal_contract_sync
formal_contract_template_manage
formal_contract_history_view
```

权限规则：

- 模板管理只授予超级管理员或指定管理员。
- 正式合同生成和打印权限可以授予普通业务人员。
- 一键同步交易合同必须同时具备正式合同同步权限和现有 `contract_create` 权限。
- 用户仍需通过现有合同数据访问范围校验。
- 前端不显示按钮不能替代后端权限校验。

## 9. 与现有模块的隔离规则

必须遵守：

1. 交易合同页面不再增加“打印正式合同”入口。
2. 现有交易合同的发货单打印入口保持不变。
3. 现有对账单打印和导出保持不变。
4. 正式合同文件存放在独立目录。
5. 正式合同草稿和生成记录使用独立数据表。
6. 不把正式合同记录写入交易记录表。
7. 不重复创建产品、公司基础表，能关联则关联。
8. 同步交易合同时调用现有创建服务。
9. 生成正式合同只读现有交易数据，不改变回款、开票和发货状态。
10. 所有数据库迁移采用新增表和索引的兼容方式。

## 10. 测试和验收

### 10.1 甲方数据

- 下拉选择已有公司。
- 模糊搜索已有公司。
- 输入新公司并自动保存。
- 已有公司自动加载最近一次正式合同信息。
- 修改当前合同不意外覆盖 ERP 公司资料。
- 新公司可以被交易合同继续选择。

### 10.2 产品数据

- 选择已有产品后自动填充编码和规格型号。
- 多产品明细生成正确。
- 产品数量、单价和总价计算正确。
- 产品库后续修改不影响历史正式合同快照。

### 10.3 模板和文件

- 管理员上传模板。
- 普通用户不能上传模板。
- 模板字段校验正确。
- 模板切换后历史文件仍可下载。
- 生成 DOCX 文件内容正确。
- 文件名安全且不会互相覆盖。

### 10.4 打印

- 正式合同详情页一键进入打印页。
- 自动调用浏览器打印。
- 手动点击打印正常。
- 打印时不显示操作按钮。
- 打印取消后数据不丢失。
- 打印完成后窗口或 iframe 正常回收。

### 10.5 同步交易合同

- 完整正式合同可以一键同步。
- 缺少公司、产品、数量时阻止同步并提示原因。
- 同步成功后可以打开对应交易合同。
- 重复点击不会重复生成交易合同。
- 交易合同现有新增、编辑、发货、回款流程不受影响。

### 10.6 回归测试

必须回归：

- ERP 合同新增、编辑、查看。
- 产品和公司选择。
- 发货单打印和导出。
- 回款和开票状态。
- 对账单生成、打印和导出。
- 合同附件上传。
- 用户和角色权限。
- 数据库迁移和应用启动。
