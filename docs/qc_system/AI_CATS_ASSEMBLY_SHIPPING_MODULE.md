# AI CATS 装配/出厂模块开发文档

> 权限说明：本文档中的“测试期全部开放”和旧“指导/验收人员”称谓已废止。现行权限、身份与用户可见命名以 `AI_CATS_MULTI_IDENTITY_ACCESS_CONTROL.md` 为准，装配执行方统一显示为“供应商”。

## 1. 目标

本模块作为 `AI CATS` 的独立一级模块，与现有 `配件生产`、`研究/实验` 平级。它的目标是把“产品模板建立 -> 发起装配 -> 质量检测 -> 验收/出厂”这一整条流程独立出来，同时直接复用 `配件生产` 模块已经稳定运行的 `工件库` 作为底层库存来源。

本轮开发重点：

1. 新增独立导航：`产品库`、`工件库`、`发起装配`、`质量检测`、`验收/出厂`
2. `工件库` 直接复用现有配件生产模块内容
3. 新建 `产品库`，支持产品基础信息、装配结构（BOM）、装配单、备注
4. 新建 `发起装配` 流程，按装配产品模板复制快照
5. 新建装配模块专属 `质量检测`、`验收/出厂`
6. 建立 “发起时校验库存 / 验收完成时正式扣减库存 / 回退与取消时可恢复” 的库存闭环
7. 正式权限收口：仅管理层或具有对应 AI CATS 身份和模块范围的用户可进入

---

## 2. 模块边界

### 2.1 独立性要求

装配/出厂模块必须与 `配件生产`、`研究/实验` 在以下层面完全独立：

1. 独立数据表
2. 独立路由前缀
3. 独立模板页面
4. 独立状态流转
5. 独立历史记录

允许复用：

1. AI CATS 整体导航壳层
2. 文件上传、图片/PDF 预览、动态卡片、时间线等 UI 组件
3. 配件生产的工件库数据
4. 生产模块成熟的质检/验收交互模式

明确禁止：

1. 直接复用 `qc_work_orders` 作为装配单主表
2. 直接混用 `research_*` 表
3. 使用前端 if/else 假装是独立模块，但后台仍写入旧表

## 3. 页面结构

### 3.1 顶部导航

进入装配/出厂模块后，导航项如下：

1. `产品库`
2. `工件库`
3. `发起装配`
4. `质量检测`
5. `验收/出厂`

说明：

1. `工件库` 直接指向现有 `配件生产` 工件库内容，但导航语义属于装配模块
2. 当前模块标识应突出为 `装配/出厂`
3. 返回模块选择页后，才能切换到别的一级模块

### 3.2 产品库

产品库页面类比工件库：

1. 顶部显示“新增产品”按钮
2. 支持关键字检索：产品编号 / 产品名称
3. 列表显示：
   - 产品编号
   - 产品名称
   - 创建人
   - BOM 配件数量
   - 装配单数量
   - 备注数量
   - 更新时间

### 3.3 产品详情 / 编辑页

分四张主卡片：

1. `基础信息`
   - 产品编号
   - 产品名称
   - 创建人
2. `装配结构`
   - 动态增加配件
   - 每行字段：工件选择、工件名称/编号联想、单件用量
   - 至少保留 2 行
3. `装配单`
   - 结构参照工件库中的“作业指导书”
   - 支持多条
4. `备注`
   - 结构参照工件库备注

## 4. 数据结构

### 4.1 新增表

1. `assembly_products`
   - 装配产品模板主表
2. `assembly_product_components`
   - 产品 BOM 结构
3. `assembly_product_attachments`
   - 产品模板附件（装配单、备注）
4. `assembly_orders`
   - 发起装配后的订单主表
5. `assembly_order_components`
   - 发起时冻结的 BOM 快照
6. `assembly_order_attachments`
   - 发起时冻结的附件快照与运行期附件
7. `assembly_inspection_records`
   - 装配质检记录
8. `assembly_acceptance_signatures`
   - 双方验收签字
9. `assembly_order_histories`
   - 不可变更历史记录

### 4.2 与工件库的关系

`assembly_product_components.workpiece_id` 与 `qc_workpieces.id` 建立关联。

作用：

1. 产品模板可引用工件库中的任意工件
2. 发起装配时冻结当前工件编码、名称、单件用量
3. 最终验收通过后按冻结值扣减工件库存

## 5. 核心流程

### 5.1 产品模板建立

1. 用户新增产品
2. 录入基础信息
3. 建立装配结构（BOM）
4. 上传装配单
5. 填写备注
6. 保存后形成装配产品模板

校验规则：

1. 产品编号唯一
2. 装配结构至少 2 个配件
3. 每个配件必须选择有效工件
4. 每个配件数量必须大于 0
5. 装配单至少 1 条

### 5.2 发起装配

1. 选择装配产品
2. 自动带出产品快照
3. 填写批次编号、装配数量、装配负责人、指导/验收人员
4. 上传本批次补充文件：
   - `生产登记单`
   - `生产合格证`
   - `备注批注`
5. 选择：
   - 保存草稿
   - 完成并进入质量检测

### 5.3 质量检测

整体交互风格沿用配件生产模块：

1. 对每一条快照附件进行通过 / 不通过判断
2. 必要时上传合格报告
3. 保存草稿或正式提交
4. 不通过则退回发起装配
5. 通过则进入验收/出厂

### 5.4 验收/出厂

整体交互逻辑沿用配件生产模块：

1. 双方确认模式
2. 管理层可代签
3. 支持取消确认
4. 支持回退

区别：

1. 当双方确认完成后，不是给库存加数，而是从 `工件库` 扣减本次消耗数量

## 6. 库存逻辑设计

### 6.1 为什么不能只在最后扣减

如果只在“最终验收完成”时扣减，而发起时不做任何保护，会出现：

1. 当前库存 100
2. A 装配单申请消耗 80
3. B 装配单申请消耗 80
4. 两个单都成功发起
5. 最终扣减时总消耗 160，导致库存穿透

因此必须引入“预占”概念。

### 6.2 设计原则

1. `qc_workpieces.stock_quantity` 继续表示物理库存
2. 装配单发起成功后，不立即改写物理库存
3. 但会把本单的 BOM 消耗量视为“预占”
4. 新装配单发起时，按 `可用库存 = 物理库存 - 已预占未扣减数量` 进行校验
5. 最终验收完成时，才真正扣减 `stock_quantity`
6. 如果装配单被退回、删除、回退到草稿，预占自动释放
7. 如果已完成扣减后又取消最终确认，则把库存补回

### 6.3 预占范围

会占用库存的装配单状态：

1. `assembly_pending`
2. `assembly_completed`
3. `inspection_pending`
4. `inspection_completed`
5. `accepted` 但尚未执行回滚恢复前已扣减，不再重复计入预占

不占用库存的状态：

1. `draft`
2. `rejected`

### 6.4 发起时校验

点击“完成并进入质量检测”前：

1. 计算本单每个 BOM 项的总消耗量：
   - `总需求 = 单件用量 * 装配数量`
2. 查询该工件的当前库存
3. 扣除其他在途装配单的已预占量
4. 如果可用库存不足，则报错并停留在当前页

提示文案：

- `工件 {编码/名称} 库存不足，当前可用 {x}，本次需消耗 {y}`

### 6.5 最终验收扣减

双方验收完成后：

1. 若本单尚未扣减过库存，则逐项执行扣减
2. 记录 `inventory_posted_at`
3. 写入历史记录

### 6.6 回滚恢复

1. 若已完成库存扣减，且后续取消签字或回退验收，则库存加回
2. 同时清空 `inventory_posted_at`
3. 历史中记录恢复动作

## 7. 模糊搜索

### 7.1 适用场景

产品编辑页中的 BOM 选择工件时，需要支持按以下字段部分命中：

1. 工件编号
2. 工件名称

### 7.2 交互方式

1. 输入框键入关键词
2. 下拉联想展示候选工件
3. 点击候选项后，写入隐藏 `workpiece_id`
4. 若用户清空文本，隐藏值同步清空

### 7.3 返回结构

接口返回：

1. `id`
2. `workpiece_code`
3. `workpiece_name`
4. `workpiece_type`
5. `stock_quantity`

## 8. 附件映射

### 8.1 产品模板页

1. `装配单`
   - 复用“作业指导书”那种多条卡片结构
2. `备注`
   - 复用工件备注结构

### 8.2 发起装配页

从产品模板复制快照，并映射为：

1. 产品模板 `装配单` -> 装配订单中的 `生产登记单`
2. 本次上传的补充文件 -> `生产登记单批注`
3. 本次上传的 `生产合格证`
4. 模板备注 -> 订单备注
5. 本次上传的 `备注批注`

## 9. 权限与测试策略

### 9.1 正式角色语义

采用 AI CATS 正式多身份模型：

1. `controller`（质量控制人）作为装配负责人，默认覆盖配件生产和装配/出厂
2. `supplier`（供应商）作为装配执行及质量确认方，默认覆盖配件生产和装配/出厂
3. `general_manager` / `gm_assistant` / 超级管理员作为管理层，拥有全部 AI CATS 权限

### 9.2 正式权限规则

测试期“所有已激活 ERP 用户完整使用 AI CATS”的规则已经废止。

正式运行规则：

1. ERP 角色和 AI CATS 身份独立保存，共享账号的 AI CATS 启停不影响 ERP 登录。
2. 普通用户必须拥有已审批的 `controller` 或 `supplier` 身份，并启用装配模块范围。
3. 普通用户只能查看和操作自己参与的产品、订单、检测、验收与出厂记录。
4. 总经理、总经理助理和超级管理员拥有全模块及身份管理权限。
5. 生产配置强制关闭遗留测试期全开放开关。

1. 创建产品 / 编辑产品
2. 创建装配单 / 保存草稿
3. 应用产品快照
4. 完成装配并进入质检
5. 保存质检草稿
6. 提交质检
7. 验收确认
8. 库存扣减
9. 取消确认
10. 验收回退
11. 库存恢复

要求：

1. 时间不可修改
2. 操作人可追溯
3. 历史只增不改
