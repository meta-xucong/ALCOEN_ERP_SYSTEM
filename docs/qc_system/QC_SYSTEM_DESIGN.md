## 1. 系统定位

质量控制系统（Quality Control System，简称 QC）是 ALCOEN 企业信息化平台的第二个子系统，与现有的 ERP 子系统共享账号认证基础设施，但业务数据、权限体系、功能模块完全独立。

### 1.1 双系统关系

```
┌─────────────────────────────────────────┐
│           ALCOEN 门户入口 (/)            │
│    [企业资源计划管理系统]  [质量控制系统]   │
└─────────────────────────────────────────┘
                    │
        ┌───────────┴───────────┐
        ▼                       ▼
┌───────────────┐       ┌───────────────┐
│   ERP 子系统   │       │   QC 子系统    │
│  /erp/...     │       │  /qc/...      │
│  合同/交易/对账 │       │  质控/质检/验收 │
└───────────────┘       └───────────────┘
        │                       │
        └───────────┬───────────┘
                    ▼
            ┌───────────────┐
            │  共享认证中心   │
            │  users/roles  │
            │  邮箱验证码    │
            │  信任设备     │
            └───────────────┘
```

## 2. 用户与角色体系

### 2.1 QC 角色定义

| 角色代码 | 角色名称 | 级别 | 说明 |
|---------|---------|------|------|
| `superadmin` | 超级管理员 | 100 | 与 ERP 一致，可见可操作所有数据 |
| `general_manager` | 总经理 | 80 | 与 ERP 一致，可见所有数据 |
| `gm_assistant` | 总经理助理 | 70 | 与 ERP 一致，可见所有数据，可验收 |
| `qc_controller` | 质量控制员 | 55 | QC 专属，负责创建工件订单、质控、验收 |
| `qc_inspector` | 质量检测员 | 45 | QC 专属，负责执行质量检测 |

### 2.2 账号共享机制

QC 系统复用 ERP 的 `users` 表作为**主账号表**，通过 `qc_user_bindings` 表实现同一账号在 QC 中的角色绑定。

**场景说明：**

1. **ERP 老用户首次登录 QC**
   - 输入 ERP 账号密码登录 QC
   - 系统检测到 `users` 表存在但 `qc_user_bindings` 不存在
   - 跳转至 `/auth/qc_role_apply` 选择 QC 角色并提交申请
   - 管理员审核通过后，方可进入 QC

2. **从 QC 注册页面新注册**
   - 如果 username 已存在于 ERP：复用该账号，仅添加 `qc_user_bindings`（待审核）
   - 如果 username 不存在：创建新 `users` 记录 + `qc_user_bindings`（待审核）

3. **密码同步**
   - 因为共享 `users.password_hash`，任何子系统中修改密码立即在另一子系统生效

## 3. 业务模块设计

### 3.1 模块总览

| 模块 | 入口 | 主导角色 | 可见角色 | 核心功能 |
|------|------|---------|---------|---------|
| 质量控制 | `/qc/quality-control/` | 质量控制员 | 质量控制员 | 创建/编辑工件订单，发起质控流程 |
| 质量检测 | `/qc/quality-inspection/` | 质量检测员 | 质量控制员(只读)、质量检测员 | 对工件订单各栏目进行 √/× 判定 |
| 验收模块 | `/qc/acceptance/` | 质量控制员 | 质量控制员、质量检测员 | 双角色确认验收，可回退，可打印 |

### 3.2 工件订单（Work Order）数据模型

一个工件订单包含以下结构化信息：

#### 基础信息（文字）
- **批次编号** (`batch_no`): 系统内唯一，必填
- **工件名称** (`workpiece_name`): 必填
- **生产数量** (`quantity`): 必填
- **质量控制负责人** (`controller_id`): 自动绑定创建人，只读

#### 图文信息（附件）
- **图纸** (`drawing`): 1 个，必填，图片格式
- **作业指导书** (`instruction`): 1 个，必填，图片/PDF 格式
- **检测点** (`inspection_points`): 至少 1 个，可无限添加，每项含文字描述 + 图片，必填

#### 备注信息（附件）
- **备注** (`remarks`): 默认 0 个，可无限添加，每项含文字内容 + 图片
- 每个备注可单独设置 `is_required`（必填/选填）

### 3.3 工作流状态机

```
                    ┌─────────────────┐
                    │   qc_pending    │  ← 质控未完成（初始状态）
                    │   质控未完成     │
                    └────────┬────────┘
                             │ 质量控制员点击"完成"
                             ▼
                    ┌─────────────────┐
                    │  qc_completed   │  ← 质控已完成
                    │   质控已完成     │
                    └────────┬────────┘
                             │ 推送给质量检测员
                             ▼
                 ┌───────────────────────┐
                 │   inspection_pending  │  ← 质检未完成
                 │     质检未完成         │
                 └───────────┬───────────┘
                             │
           ┌─────────────────┼─────────────────┐
           │                                   │
           ▼ 全部 √                              ▼ 存在 ×
┌───────────────────────┐           ┌───────────────────────┐
│ inspection_completed  │           │       rejected        │
│     质检已完成         │           │      质检不合格       │
└───────────┬───────────┘           └───────────┬───────────┘
            │                                   │
            │ 进入验收                           │ 退回质控模块
            ▼                                   ▼
    ┌───────────────┐                   ┌───────────────┐
    │   accepted    │                   │   qc_pending  │
    │   验收已完成   │                   │   重新修改     │
    └───────────────┘                   └───────────────┘
```

### 3.4 状态流转规则

| 当前状态 | 触发条件 | 下一状态 | 执行人 | 系统行为 |
|---------|---------|---------|--------|---------|
| `qc_pending` | 质控员点击"完成"且所有必填项已填 | `qc_completed` | 质量控制员 | 记录 `qc_completed_at`，推送至质检 |
| `qc_completed` | （系统推送） | `inspection_pending` | 系统 | 质检员可见 |
| `inspection_pending` | 质检员点击"质检合格"且全部 √ | `inspection_completed` | 质量检测员 | 记录 `inspection_completed_at` |
| `inspection_pending` | 质检员点击"质检不合格"且存在 × | `rejected` | 质量检测员 | 记录 `rejected_at`，保留 × 标记 |
| `rejected` | 质控员修改后重新点击"完成" | `qc_completed` | 质量控制员 | 清除上次质检记录，重新推送 |
| `inspection_completed` | 质控员+质检员双签确认 | `accepted` | 双角色 | 记录 `accepted_at`，状态锁定 |
| `accepted` | 管理员/质控员点击"撤销验收" | `qc_pending` 或 `inspection_pending` | superadmin/GM/GM助理/质控员 | 记录回退原因 |

## 4. 页面交互设计

### 4.1 质量控制详情页

页面分区从上至下：

1. **订单状态栏**
   - 左侧显示当前状态标签（颜色按状态映射）
   - 右侧显示批次编号和创建时间

2. **基础信息卡片**
   - 批次编号输入框（唯一校验）
   - 工件名称输入框
   - 生产数量输入框
   - 质量控制负责人（只读文本）

3. **图纸卡片**
   - 标题"图纸"
   - 图片上传区域（支持拖拽/点击）
   - 上传后显示缩略图和删除按钮

4. **作业指导书卡片**
   - 标题"作业指导书"
   - 文件上传区域（图片/PDF）
   - 上传后显示文件名和预览/删除按钮

5. **检测点卡片**
   - 标题"检测点"
   - 至少保留 1 个检测点行
   - 每行结构：
     - 序号（自动）
     - 文字输入框（检测点名称/描述）
     - 图片上传模块
     - 删除按钮（当只剩 1 个时隐藏）
   - 卡片底部："+ 新增检测点" 按钮

6. **备注卡片**
   - 标题"备注"
   - 默认显示"暂无备注，点击下方按钮添加"
   - 每行结构：
     - 文字输入框
     - 图片上传模块（选填）
     - 必填/选填 开关
     - 删除按钮
   - 卡片底部："+ 新增备注" 按钮

7. **完成区域（页面最底部）**
   - 下拉框：选择目标质量检测员（加载所有 `qc_inspector` 角色用户）
   - "完成并推送至质检" 按钮
   - 按钮在未满足条件时显示 `disabled` 样式并不可点击
   - 前端实时校验：遍历所有 `is_required=1` 的字段和图片，全部非空则启用按钮

### 4.2 质量检测详情页

页面分区从上至下：

1. **订单状态栏**
   - 显示当前状态

2. **基础信息展示**
   - 只读展示所有文字信息

3. **各栏目质检区**
   - 每个栏目（图纸、作业指导书、检测点、备注）渲染为一个卡片行
   - 左侧：栏目内容（文字+图片预览）
   - 右侧：质检审核区
     - 圆形 `√` 按钮（绿色边框，点击后填充绿色）
     - 圆形 `×` 按钮（红色边框，点击后填充红色）
     - 两个按钮互斥（点击一个自动取消另一个）
     - 备注输入框（可选填）
   - 整行背景色随选择变化：
     - 选 `√` → `rgba(25, 135, 84, 0.08)` 背景
     - 选 `×` → `rgba(220, 53, 69, 0.08)` 背景
     - 未选 → 无背景色

4. **提交区域（页面最底部）**
   - "质检合格，进入交付页面" 按钮（`btn-success`）
   - "质检不合格，退回质量控制流程" 按钮（`btn-danger`）
   - 两个按钮初始状态 `disabled`
   - 当且仅当所有栏目都已选择 `√` 或 `×` 时启用对应按钮

### 4.3 验收确认页

页面分区从上至下：

1. **验收标题**
   - 大字显示"工件验收确认单"
   - 批次编号、日期

2. **信息汇总表格**
   - 类似 ERP 合同明细页的表格风格
   - 行项目：基础信息、图纸（含缩略图）、作业指导书、每个检测点、每个备注
   - 质检记录列：显示该栏目对应的 `√` / `×` 结果和质检备注

3. **双签确认区（页面最底部）**
   - 左侧卡片："质控员已验收" 按钮
     - 仅 `qc_controller` 可点击
     - 点击后变为 "已确认 ✓" 并 disabled
   - 右侧卡片："质检员已验收" 按钮
     - 仅 `qc_inspector` 可点击
     - 点击后变为 "已确认 ✓" 并 disabled
   - 两个都确认后，页面顶部状态自动刷新为 `accepted`

4. **管理操作区**
   - "撤销验收，退回修改" 按钮（仅 superadmin/GM/GM助理/质控员可见）
   - 点击后弹出模态框：选择回退目标（质控/质检）+ 填写原因
   - "打印验收清单" 按钮（`btn-outline-primary`）
     - 点击打开 `/qc/acceptance/<id>/print` 新标签页

## 6. 文件上传规范

### 6.1 存储路径

```
static/
  uploads/
    qc/
      {work_order_id}/
        drawings/
          {filename}
        instructions/
          {filename}
        inspection_points/
          {point_id}_{filename}
        remarks/
          {remark_id}_{filename}
```

### 6.2 允许格式

- 图片：`jpg`, `jpeg`, `png`, `gif`, `webp`, `bmp`
- 文档：`pdf`
- 单文件大小限制：16MB（继承全局 `MAX_CONTENT_LENGTH`）

### 6.3 命名规范

上传文件统一重命名为时间戳+随机后缀格式，避免中文文件名问题：
```
{timestamp}_{random8}_{original_name_safe}
```

## 7. 验收清单打印页

### 7.1 页面特性
- 独立页面 `/qc/acceptance/<id>/print`
- 移除导航栏和页脚，纯内容展示
- 添加 `@media print` 样式优化打印效果
- 页眉显示公司 Logo 和系统名称
- 页脚显示打印日期和"本验收单一式两份"

### 7.2 内容结构
1. 标题：工件验收确认单
2. 基本信息表格（批次号、工件名、数量、负责人、质检员）
3. 各栏目明细表格（含图片占位，打印时显示文件名）
4. 质检结果汇总
5. 签字确认区域（预留空白行供手写签字）
6. 底部提示：打印日期、系统生成

## 8. 与 ERP 的集成边界

### 8.1 共享组件（不改动，直接复用）
- 登录认证中心 (`auth_bp`)
- 邮箱验证码系统 (`VerificationCode`, `EmailService`)
- 受信任设备系统 (`TrustedDevice`)
- 用户管理基础功能 (`user_bp` 中的查看/编辑资料/改密)
- 主题偏好系统 (`theme_preference`)
- 系统设置 (`settings_bp`)

### 8.2 QC 专属扩展
- `qc_user_bindings` — QC 角色绑定
- `qc_work_orders` 及关联表 — QC 业务数据
- `app/routes/qc.py` — QC 路由
- `app/services/qc_service.py` — QC 业务逻辑
- `templates/qc/*` — QC 模板

### 8.3 ERP 需微调的边界
- `main.index` 路由从 `/` 迁移至 `/erp/`
- `base.html` 中的首页链接和 Logo 链接改为 `url_for('main.index')`（即 `/erp/`）
- `auth/login.html` 根据入口参数显示不同标题和注册链接
- `user/pending.html` 和 `user/list.html` 增加 QC 待审核用户的显示和审批入口
