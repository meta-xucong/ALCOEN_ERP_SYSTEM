# ERP 正式合同打印模块开发文档

## 1. 文档信息

- 文档名称：ERP 正式合同打印模块开发文档
- 文档版本：v1.0
- 日期：2026-08-07
- 状态：本地开发完成，待业务验收
- 适用系统：ALCOEN ERP 合同模块

## 2. 需求背景

在合同详情页面增加“打印正式合同”功能。管理员可以维护正式合同模板，普通用户不能修改模板，只能在自己有权查看的合同中，根据合同订单内容生成并打印正式合同。

打印交互必须沿用当前发货单、对账单的浏览器打印方式：

1. 合同详情页点击“打印正式合同”。
2. 打开独立打印页面或内嵌打印页。
3. 页面自动调用浏览器打印窗口。
4. 用户选择本地打印机后完成打印。
5. 支持手动再次点击“打印”。
6. 打印结束后关闭打印窗口或回收内嵌页面。

同时保留 DOCX 文件生成能力，便于下载、编辑和归档。

## 3. 设计目标

### 3.1 必须实现

- 合同详情页增加“打印正式合同”入口。
- 根据当前合同内容生成正式合同。
- 使用管理员上传的合同模板生成 DOCX 文件。
- 使用浏览器打印窗口完成打印。
- 普通用户只能根据订单生成和打印，不能修改模板。
- 管理员可以上传、预览、启用、停用和切换模板。
- 模板支持版本管理。
- 每次生成的合同记录使用的模板版本和生成时间。
- 生成过程只读合同数据，不修改合同、发货、回款和对账数据。

### 3.2 明确不包含

- 不改动现有发货单打印逻辑。
- 不改动现有对账单生成和导出逻辑。
- 不改变合同金额、回款状态、开票状态和发货状态的计算方式。
- 不自动修改合同内容。
- 第一阶段不实现服务器直接控制指定打印机。
- 不允许普通用户上传或替换合同模板。

## 4. 核心交互方案

### 4.1 合同详情页

在合同详情页增加按钮：

```text
打印正式合同
```

按钮显示条件：

- 当前用户已登录。
- 当前用户有权查看该合同。
- 当前用户拥有正式合同生成/打印权限。
- 系统存在一个已启用的正式合同模板。

如果没有启用模板，按钮可以显示为不可用状态，并提示：

```text
暂未配置正式合同模板，请联系管理员。
```

### 4.2 打印流程

打印流程沿用现有发货单打印机制：

1. 用户点击“打印正式合同”。
2. 后端读取当前合同和启用模板。
3. 生成本次合同的 DOCX 文件。
4. 根据同一份合同数据生成打印展示页。
5. 打印页加载后自动调用 `window.print()`。
6. 用户可以取消打印，也可以再次点击页面上的“打印”按钮。
7. 打印结束后触发 `afterprint`，关闭新窗口或回收内嵌 iframe。

打印页应包含：

- 打印按钮
- DOCX 下载按钮
- 返回合同按钮
- 合同正文
- 合同编号和生成时间

打印页的操作按钮、导航栏和辅助信息必须使用 `@media print` 隐藏，不能出现在纸质合同中。

### 4.3 DOCX 文件

建议统一使用现代 Word 格式：

```text
.docx
```

不建议直接生成旧式 `.doc`，原因是旧格式对中文、表格、图片和分页的兼容性较差。

如果后续确实需要 `.doc`，可以在部署环境具备 LibreOffice 后增加兼容转换，但不作为第一阶段的默认输出格式。

## 5. 模块边界和代码组织

正式合同功能必须作为独立子模块开发，不能把模板逻辑直接塞进现有发货单或对账单逻辑中。

建议目录结构：

```text
app/
├── models.py
├── routes/
│   └── official_contract.py
├── services/
│   └── official_contract_service.py
└── utils/
    └── official_contract_template.py

templates/
└── official_contract/
    ├── print.html
    ├── template_list.html
    ├── template_form.html
    └── template_preview.html

static/
└── official_contract/
    └── official-contract-print.css

data/
└── official_contract_templates/

exports/
└── official_contracts/
```

建议使用独立 Blueprint：

```text
official_contract_bp
```

建议 URL 命名空间：

```text
/contract/<contract_id>/official/print
/contract/<contract_id>/official/download
/official-contract/templates
```

合同详情页只增加入口链接，不修改现有打印路由。

## 6. 模板管理设计

### 6.1 管理员功能

管理员可以：

- 上传新模板。
- 填写模板名称和版本说明。
- 查看模板列表。
- 预览模板。
- 校验模板占位符。
- 启用模板。
- 停用模板。
- 上传新版本。
- 查看模板使用记录。

同一时间只允许一个正式合同模板处于“启用”状态。

启用新模板时：

1. 旧模板自动变为停用。
2. 历史生成记录仍保留原模板版本。
3. 已生成的合同文件不能因为模板切换而改变。

### 6.2 模板上传规则

第一阶段建议只允许：

```text
.docx
```

上传时必须执行：

- 文件扩展名检查。
- MIME 类型检查。
- 文件大小限制。
- 文件名安全化。
- 文件哈希计算。
- 占位符语法检查。
- 未知字段检查。
- 文件保存到独立目录。

不允许将模板直接保存到 `templates/` 代码目录，避免运行时上传文件污染代码和 Git 仓库。

### 6.3 模板占位符与固定版式

模板使用受控字段，不允许模板执行任意 Python 代码。

基础字段示例：

```text
{{ contract.contract_no }}
{{ contract.contract_date }}
{{ company.name }}
{{ company.address }}
{{ company.contact_person }}
{{ company.phone }}
{{ contract.total_amount }}
{{ contract.total_amount_upper }}
```

产品明细使用循环：

```text
{% for item in contract.items %}
{{ item.product_code }}
{{ item.product_name }}
{{ item.quantity }}
{{ item.unit }}
{{ item.unit_price }}
{{ item.total_amount }}
{% endfor %}
```

可支持条件字段：

```text
{% if contract.payment_terms %}
{{ contract.payment_terms }}
{% endif %}
```

正式开发前需要根据实际模板确定最终字段清单。当前提供的 `配件合同模版.docx` 已完成结构适配：它没有 Jinja 占位符，系统会按固定版式识别合同编号表、产品明细表、条款段落和甲乙方资料表；后续若模板改为带占位符的 DOCX，则自动切换到占位符渲染模式。

## 7. 合同数据来源

正式合同生成必须使用明确的数据来源，不能无条件读取所有历史交易记录。

### 7.1 默认数据来源

- 合同编号：当前合同。
- 合同日期：当前合同。
- 客户名称和公司信息：当前合同关联公司。
- 产品明细：当前合同的发货产品计划。
- 产品编码、产品名称、型号、单位：当前合同产品计划。
- 数量、单价、总价：当前合同产品计划。
- 合同总价：当前合同当前有效明细计算结果。
- 备注：当前合同备注。

### 7.2 默认不自动加入

以下信息不得默认混入正式合同：

- 历史发货批次。
- 其他合同的产品。
- 其他客户的交易记录。
- 与当前合同无关的回款记录。
- 与当前合同无关的附件。

如果后续模板确实需要发货记录或付款记录，应增加明确的模板字段和业务开关，例如：

```text
是否包含当前合同发货计划
是否包含当前合同付款条款
是否包含当前合同回款摘要
```

不能通过“读取所有关联记录”的方式实现。

### 7.3 财务字段权限

正式合同可能包含单价和总价。生成时必须继续遵守现有财务权限：

- 有财务查看权限：正常显示金额。
- 无财务查看权限：如果模板包含金额字段，禁止生成或根据业务规则显示脱敏内容。

第一阶段建议采用更安全的规则：

```text
无财务查看权限时，不允许生成包含金额字段的正式合同。
```

这样可以避免普通用户通过正式合同文件绕过现有金额权限。

## 8. 数据模型设计

新增模型，不修改现有合同核心字段。

### 8.1 ContractTemplate

建议字段：

| 字段 | 说明 |
|---|---|
| id | 主键 |
| name | 模板名称 |
| version | 模板版本 |
| original_filename | 原始文件名 |
| stored_path | 服务端保存路径 |
| file_hash | 文件哈希 |
| status | active/inactive |
| description | 版本说明 |
| uploaded_by_id | 上传人 |
| created_at | 上传时间 |
| activated_at | 启用时间 |
| deactivated_at | 停用时间 |

### 8.2 OfficialContractDocument

建议字段：

| 字段 | 说明 |
|---|---|
| id | 主键 |
| contract_id | 合同 ID |
| template_id | 模板 ID |
| template_version | 生成时的模板版本 |
| generated_by_id | 生成人 |
| docx_path | 生成文件路径 |
| snapshot_json | 生成时的数据快照 |
| generated_at | 生成时间 |
| printed_at | 最近打印时间 |
| print_count | 打印次数 |
| file_hash | 生成文件哈希 |

生成记录采用追加方式，不覆盖历史文件。

## 9. 权限设计

新增权限建议：

```text
contract_official_generate
正式合同生成和打印

contract_template_manage
正式合同模板管理

contract_official_history_view
查看正式合同生成记录
```

权限规则：

- `contract_template_manage`：仅超级管理员或被明确授权的管理员。
- `contract_official_generate`：由管理员根据实际角色授权。
- `contract_official_history_view`：管理员默认拥有，普通用户默认不拥有。
- 生成合同仍必须通过现有 `can_view_contract(contract)` 校验。
- 用户只能生成自己有权查看的合同。
- 模板管理权限不能自动扩大合同查看范围。

权限校验必须同时存在于：

1. 页面按钮显示。
2. 后端路由。
3. 文件下载路由。
4. 模板管理接口。

不能只依赖前端隐藏按钮。

## 10. 文件存储和安全

### 10.1 存储隔离

模板和生成文件使用独立目录：

```text
data/official_contract_templates/
exports/official_contracts/
```

不得与现有：

- `static/uploads/`
- 发货附件
- 质量控制附件
- 普通合同附件

混用目录。

### 10.2 文件安全

- 所有文件名使用安全化名称。
- 下载必须经过权限校验。
- 不允许通过用户提交的路径直接读取文件。
- 生成文件按合同 ID 和生成记录 ID 命名。
- 模板停用不删除历史生成文件。
- 删除模板前检查是否存在历史引用。
- 删除操作默认改为停用，不做物理删除。

## 11. 兼容和不破坏规则

本功能上线前必须遵守以下底线：

1. 不修改现有合同表中的业务字段。
2. 不修改现有发货记录、发货批次和发货单打印查询逻辑。
3. 不修改现有回款、开票和对账单计算逻辑。
4. 不复用发货单的批次变量。
5. 不把正式合同生成记录写入发货交易表。
6. 不覆盖历史合同附件。
7. 数据库变更只能新增表、索引和必要的关联字段。
8. 所有新增路由使用独立命名空间。
9. 所有新模板使用独立目录。
10. 模板未配置时，现有合同详情页和其他打印功能仍然正常。

## 12. 测试方案

### 12.1 模板测试

- 上传合法 DOCX 模板。
- 上传非 DOCX 文件。
- 上传超过大小限制的文件。
- 模板包含未知占位符。
- 模板缺少必填字段。
- 模板包含多个产品明细。
- 模板包含零数量、空备注和长公司名称。
- 模板包含中文、英文、特殊符号。
- 模板切换后历史版本仍可追溯。

### 12.2 权限测试

- 管理员可以上传和启用模板。
- 普通用户不能访问模板管理页面。
- 无合同查看权限的用户不能生成合同。
- 有合同查看权限且有正式合同权限的用户可以生成和打印。
- 无财务权限用户不能生成包含金额的模板。
- 直接访问后端 URL 不能绕过权限。

### 12.3 打印测试

- 合同详情页按钮显示正确。
- 打印页面返回 HTTP 200。
- 页面自动调用浏览器打印窗口。
- 手动点击打印按钮正常。
- 打印时不出现导航栏和操作按钮。
- 打印完成后 iframe 或窗口正确回收。
- 取消打印不会删除生成记录。
- 连续生成两次不会相互覆盖。

### 12.4 回归测试

至少执行：

```text
合同列表、合同新增、合同编辑、合同详情
发货单打印和导出
对账单生成、查看和导出
回款记录和开票状态
合同附件上传和查看
权限登录与角色权限
```

同时执行：

- 修改文件的 `py_compile`。
- 数据库表结构检查。
- 模板变量与后端字段检查。
- 全量测试。
- 本地启动和浏览器验收。

## 13. 开发阶段划分

### Phase 1：独立模块和数据结构

- 新增模型和迁移脚本。
- 新增权限常量。
- 新增独立路由、服务和模板目录。
- 增加模板上传、列表和启停功能。

### Phase 2：合同生成

- 建立合同数据适配器。
- 实现 DOCX 模板填充。
- 实现生成记录和数据快照。
- 实现 DOCX 下载。

### Phase 3：浏览器打印

- 实现正式合同打印页。
- 沿用发货单的 iframe 和 `window.print()` 机制。
- 增加自动打印、手动打印和打印后回收。
- 完成页面分页和纸张样式。

### Phase 4：审计和回归

- 权限审计。
- 数据来源审计。
- 历史合同和模板版本审计。
- 全量回归测试。
- 本地验收后再提交 GitHub。

## 14. 本地实现结果与验收项

当前已完成：

- 甲方档案和正式合同独立数据模型。
- 选择已有公司、输入新公司、最近一次信息回填。
- ERP 产品库模糊搜索和产品快照。
- 固定版式与占位符 DOCX 双模式生成。
- 浏览器打印、DOCX 下载、生成历史和数据快照。
- 一键同步到交易合同，带事务和幂等保护。
- 模板管理员权限和版本切换。
- 数据库迁移脚本、语法检查和回归测试。

上线前验收：

1. 管理员上传并启用实际模板。
2. 用一个已有甲方和一个新甲方各生成一份合同。
3. 检查多产品明细、金额大写、打印预览和 DOCX 下载。
4. 验证同步后交易合同只生成一次，原 ERP 发货、回款和对账数据不被改动。

## 15. 模板文件替换后的扩展工作

收到正式合同模板后，先不立即改业务逻辑，按以下顺序处理：

1. 检查模板格式和分页。
2. 标注所有需要自动填充的位置。
3. 建立字段映射表。
4. 确认产品明细表是否需要循环扩展。
5. 确认金额字段的权限要求。
6. 确认签字、盖章和日期位置。
7. 确认空值、长文本和多产品的排版规则。
8. 制作一份测试合同数据。
9. 先生成 DOCX 和打印预览样稿。
10. 通过验收后再接入正式合同详情页。

## 16. 验收标准

满足以下条件后才允许交付：

- 管理员可以独立维护正式合同模板。
- 普通用户无法修改模板。
- 用户只能为有权限查看的合同生成合同。
- 生成的 DOCX 内容与当前合同一致。
- 产品明细数量可正确扩展。
- 金额和权限不会泄漏。
- 浏览器打印流程与发货单、对账单一致。
- 历史生成记录可追溯模板版本。
- 不影响现有合同、发货单、对账单、回款和附件功能。
- 本地测试、回归测试和手工验收全部通过。
