# 合同产品类型优化开发文档

## 1. 目标

在 ERP 创建/编辑合同的“发货产品计划”中补齐产品类型链路：

- 从产品库选择已有产品时，自动带出产品类型；
- 手动录入新产品时，允许从已有类型候选中选择，也可以输入新类型；
- 合同保存后，新产品和合同产品计划都保存同一个产品类型；
- 新产品没有产品类型时，合同流程阻止提交，避免后续无法按类型检索；
- 旧产品或旧合同类型为空时，允许在合同编辑流程中补录类型。

## 2. 当前问题

`Product`、`ContractProduct` 已经存在 `product_type` 字段，但合同动态产品行没有把该字段完整接入：

- 产品行没有正式的产品类型输入控件；
- 选中已有产品时，`data-type` 没有回填到产品行；
- 编辑合同加载已有产品时，类型没有完整回显；
- 新产品创建分支可能把空类型写入产品库。

## 3. 实现方案

### 3.1 前端

文件：`templates/contract/form.html`

- 在产品编码、名称、型号、单位区域增加“产品类型”输入框；
- 使用 `datalist#product-type-list` 提供产品库已有类型候选；
- `onProductCodeSelect()` 和 `onProductCodeInput()` 在匹配已有产品时自动回填类型；
- 有产品类型的已有产品类型框只读，避免合同中的类型与产品库类型脱钩；
- 类型为空的历史产品仍可编辑，用于补齐旧数据；
- 手动输入新产品时类型框可编辑；
- 编辑合同通过 `addProductRowWithData()` 回显 `product_type`；
- 产品行栅格调整为 `3 + 4 + 2 + 2 + 1 = 12`，避免新增类型字段后首行换乱。

### 3.2 后端

文件：

- `app/routes/contract.py`
- `app/services/contract_service.py`
- `app/services/product_service.py`

规则：

1. 产品库已有类型时，以产品库类型为准；
2. 产品库已有但类型为空时，使用合同输入的类型补齐产品库和合同快照；
3. 产品编码不存在且合同输入为空类型时，合同路由抛出校验错误，不创建合同；
4. 合同服务保留对旧的直接服务调用的兼容性，不强制历史测试或其他旧入口立即补类型；
5. 合同内自动创建新产品使用 `auto_commit=False`，最终和合同一起提交，确保中途失败不会留下孤立产品。

### 3.3 数据库

本次不新增数据库字段，不需要迁移脚本。现有字段继续使用：

- `products.product_type`
- `contract_products.product_type`

## 4. 验收场景

### 场景 A：选择已有产品

1. 打开新增合同；
2. 在发货产品计划选择已有产品；
3. 产品类型自动显示；
4. 保存合同；
5. 产品库和合同产品计划类型一致。

### 场景 B：手动创建新产品

1. 切换到手动输入产品编码；
2. 输入新编码；
3. 选择或输入产品类型；
4. 保存合同；
5. 产品库新增产品，类型不为空；
6. 产品检索可以按该类型找到新产品。

### 场景 C：新产品不填类型

1. 输入产品编码、数量、价格但不填产品类型；
2. 点击保存；
3. 页面阻止合同提交并显示“需要填写产品类型”；
4. 产品库不产生空类型新产品。

### 场景 D：旧数据补齐

1. 编辑产品库类型为空的历史产品对应合同；
2. 在合同产品行补填类型；
3. 保存；
4. 合同快照和产品库类型都被补齐。
